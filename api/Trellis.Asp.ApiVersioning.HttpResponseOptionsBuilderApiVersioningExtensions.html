Remarks

Resolution order (per request, inside the LinkGenerator callback):

  1. HttpContext.RequestedApiVersion, if mapped to the destination endpoint.
  2. Exactly one version mapped to the destination, respecting action-level mappings.
  3. ApiVersioningOptions.DefaultApiVersion, only if mapped to the destination; otherwise throw InvalidOperationException.

Query-style injection uses "api-version", matching the default for QueryStringApiVersionReader and the conventional header name. Hosts using a non-default reader parameter name should register a custom resolver via WithRouteValueResolver(string, Func<HttpContext, string?>) directly.

Both overloads resolve the final named-route or MVC-action destination using endpoint routing. Missing or ambiguous destinations throw. Explicit pins must be mapped to the destination. URL-segment destinations receive the version in their actual :apiVersion parameter, not a duplicate query parameter. Neutral targets and targets without Asp.Versioning.ApiVersionMetadata omit version injection and remove a supplied api-version. The missing-metadata diagnostic identifies the destination endpoint.
