Authentication handler that turns Azure App Service / Container Apps built-in authentication ("Easy Auth") principal headers into an authenticated ClaimsPrincipal on HttpContext.User. Once the principal is on the context, the standard Trellis actor providers (ClaimsActorProvider / EasyAuthClaimsActorProvider) map its claims to an Actor — no bespoke header parsing in the actor layer.

Remarks

Decodes PrincipalHeaderName (X-MS-CLIENT-PRINCIPAL) — base64 JSON of the shape { "auth_typ": "...", "name_typ": "...", "role_typ": "...", "claims": [ { "typ": "...", "val": "..." } ] } — honoring name_typ / role_typ so ClaimsPrincipal.Identity.Name and role checks resolve. When the principal header is absent it falls back to the -ID / -NAME convenience headers. When no Easy Auth header is present it returns NoResult() (anonymous); a malformed principal header fails closed via Fail(string) rather than trusting partial data.

Trust precondition: see EasyAuthDefaults. Register only when the app is reachable exclusively through the Easy Auth front end.
