AddCachingActorProvider<T>(IServiceCollection)

Registers a caching decorator around the specified IActorProvider implementation. The inner provider is resolved per-scope and wrapped with CachingActorProvider so that multiple calls within the same request return the same actor instance.

public static IServiceCollection AddCachingActorProvider<T>(this IServiceCollection services) where T : class, IActorProvider

Parameters

services IServiceCollection

The service collection.

Returns

IServiceCollection

The service collection for chaining.

Type Parameters

T

The concrete IActorProvider implementation to cache.

Examples

// Pattern B(i): Custom provider with no Trellis-managed options dependencies.
services.AddCachingActorProvider<DatabaseActorProvider>();

// Pattern B(ii): Built-in provider — register the inner provider's options
// helper FIRST so IOptions<EntraActorOptions> is configured, then wrap.
services.AddEntraActorProvider(o => o.MapPermissions = ...);
services.AddCachingActorProvider<EntraActorProvider>();

// Pattern B(iii): Subclass of ClaimsActorProvider (e.g. KeycloakActorProvider).
// Inner subclass shares ClaimsActorOptions, so AddClaimsActorProvider(...)
// configures IOptions<ClaimsActorOptions> for the subclass too.
services.AddClaimsActorProvider(o => o.ActorIdClaim = "sub");
services.AddCachingActorProvider<KeycloakActorProvider>();

Remarks

Replaces the IActorProvider slot with the caching wrapper. The inner type T is registered via TryAddScoped<T>(), so repeated calls do not accumulate inner-provider descriptors.

Inner-provider dependencies are NOT auto-registered. This helper only adds T itself and IHttpContextAccessor. If T is one of the built-in providers (EntraActorProvider, ClaimsActorProvider) or a subclass thereof, you must first call the matching AddXxxActorProvider(...) helper so its IOptions<TOptions> is configured. The matching helper's Replace on the IActorProvider slot is then overwritten by this caching wrap — that is the intended composition order.

AddClaimsActorProvider(IServiceCollection, Action<ClaimsActorOptions>?)

Registers ClaimsActorProvider as the scoped IActorProvider with configurable claim mapping for any OIDC/JWT identity provider.

public static IServiceCollection AddClaimsActorProvider(this IServiceCollection services, Action<ClaimsActorOptions>? configure = null)

Parameters

services IServiceCollection

The service collection.

configure Action<ClaimsActorOptions>

Optional delegate to customize ClaimsActorOptions. Override ActorIdClaim and PermissionsClaim to match your token format.

Returns

IServiceCollection

The service collection for chaining.

Examples

// Auth0
builder.Services.AddClaimsActorProvider(opts =>
{
    opts.ActorIdClaim = "sub";
    opts.PermissionsClaim = "permissions";
});

// Keycloak
builder.Services.AddClaimsActorProvider(opts =>
{
    opts.ActorIdClaim = "sub";
    opts.PermissionsClaim = "realm_access.roles";
});

Remarks

Replaces any prior IActorProvider registration — actor-provider helpers do not stack. Pick one provider per environment (or wrap an inner provider with AddCachingActorProvider<T>(IServiceCollection)); the last AddXxxActorProvider call wins.

AddDevelopmentActorProvider(IServiceCollection, Action<DevelopmentActorOptions>?)

Registers DevelopmentActorProvider as the scoped IActorProvider for development and testing environments. Reads actor identity from the X-Test-Actor HTTP header and falls back to a configurable default actor.

public static IServiceCollection AddDevelopmentActorProvider(this IServiceCollection services, Action<DevelopmentActorOptions>? configure = null)

Parameters

services IServiceCollection

The service collection.

configure Action<DevelopmentActorOptions>

Optional delegate to customize DevelopmentActorOptions. Set DefaultPermissions to grant permissions when no header is present, or set ThrowOnMalformedHeader to false to fall back to the default actor on a malformed header instead of rejecting it (rejection is the default).

Returns

IServiceCollection

The service collection for chaining.

Examples

if (builder.Environment.IsDevelopment())
{
    builder.Services.AddDevelopmentActorProvider(options =>
    {
        options.DefaultPermissions = new HashSet<string>
        {
            "orders:create", "orders:read"
        };
    });
}
else
{
    builder.Services.AddEntraActorProvider();
}

Remarks

Security: The provider throws InvalidOperationException unconditionally when resolved outside of the Development environment, regardless of whether an X-Test-Actor header is present on the request. Use AddEntraActorProvider(IServiceCollection, Action<EntraActorOptions>?) for production deployments.

Replaces any prior IActorProvider registration — actor-provider helpers do not stack. Pick one provider per environment; the last AddXxxActorProvider call wins.

AddEasyAuthActorProvider(IServiceCollection, Action<ClaimsActorOptions>?)

Registers EasyAuthClaimsActorProvider as the scoped IActorProvider for requests authenticated by Azure App Service / Container Apps built-in authentication ("Easy Auth").

public static IServiceCollection AddEasyAuthActorProvider(this IServiceCollection services, Action<ClaimsActorOptions>? configure = null)

Parameters

services IServiceCollection

The service collection.

configure Action<ClaimsActorOptions>

Optional delegate to customize ClaimsActorOptions — set ActorIdClaim and PermissionsClaim to the claim types your upstream identity provider emits inside the Easy Auth principal.

Returns

IServiceCollection

The service collection for chaining.

Examples

builder.Services.AddAuthentication(EasyAuthDefaults.AuthenticationScheme).AddEasyAuth();
builder.Services.AddEasyAuthActorProvider(opts =>
{
    opts.ActorIdClaim = "http://schemas.microsoft.com/identity/claims/objectidentifier";
    opts.PermissionsClaim = "roles";
});
// ... app.UseAuthentication();

Remarks

This registers the actor mapping only. It does NOT authenticate the request — pair it with AddAuthentication(...).AddEasyAuth() and UseAuthentication() so EasyAuthAuthenticationHandler populates HttpContext.User from the X-MS-CLIENT-PRINCIPAL header first. Unlike the bearer providers, the resolved provider varies its response cache by the Easy Auth principal headers (see VaryByHeaders). A startup validator fails fast when this provider is registered but no Easy Auth authentication scheme is, surfacing the missing-scheme misconfiguration loudly instead of silently 401-ing every request.

Trust precondition: only register when the app is reachable exclusively through the Easy Auth front end — see EasyAuthDefaults. Never auto-enable it.

Replaces any prior IActorProvider registration — actor-provider helpers do not stack; the last AddXxxActorProvider call wins.

AddEntraActorProvider(IServiceCollection, Action<EntraActorOptions>?)

Registers EntraActorProvider as the scoped IActorProvider and configures EntraActorOptions with default Entra v2.0 claim mappings.

public static IServiceCollection AddEntraActorProvider(this IServiceCollection services, Action<EntraActorOptions>? configure = null)

Parameters

services IServiceCollection

The service collection.

configure Action<EntraActorOptions>

Optional delegate to customize EntraActorOptions. Override MapPermissions to flatten roles into granular permissions, MapForbiddenPermissions to populate deny lists, or MapAttributes to add custom ABAC attributes.

Returns

IServiceCollection

The service collection for chaining.

Examples

// Application-owned role→permissions catalog.
var rolePermissions = new Dictionary<string, IReadOnlyCollection<string>>
{
    ["orders.manager"] = ["orders:read", "orders:write"],
};

// RolePermissionProjection flattens role claims into permissions from the app-supplied
// map, skipping any role the service does not recognize (no throw on an unmapped role).
builder.Services.AddEntraActorProvider(options =>
{
    options.MapPermissions = RolePermissionProjection.ForRoleClaims(rolePermissions);
});

Remarks

Replaces any prior IActorProvider registration — actor-provider helpers do not stack. Pick one provider per environment (or wrap with AddCachingActorProvider<T>(IServiceCollection) using EntraActorProvider as the inner type); the last AddXxxActorProvider call wins.

AddNestedJsonPathClaimsActorProvider(IServiceCollection, Action<NestedJsonPathClaimsActorOptions>?)

Registers NestedJsonPathClaimsActorProvider as the scoped IActorProvider with nested-JSON claim shape support (Auth0 app_metadata.roles, Azure B2C extension_*, Okta nested claims).

public static IServiceCollection AddNestedJsonPathClaimsActorProvider(this IServiceCollection services, Action<NestedJsonPathClaimsActorOptions>? configure = null)

Parameters

services IServiceCollection

The service collection.

configure Action<NestedJsonPathClaimsActorOptions>

Optional delegate to customize NestedJsonPathClaimsActorOptions. Set ContainerClaim to the top-level claim that carries the JSON document, ActorIdPath / PermissionsPath to the dotted JSON paths inside it, and optionally the inherited flat ActorIdClaim / PermissionsClaim for the fallback when the container claim is absent or malformed.

Returns

IServiceCollection

The service collection for chaining.

Examples

// Auth0 — permissions under app_metadata.roles as a JSON array of strings.
builder.Services.AddNestedJsonPathClaimsActorProvider(opts =>
{
    opts.ActorIdClaim = "sub";
    opts.ContainerClaim = "app_metadata";
    opts.PermissionsPath = "roles";
});

Remarks

Replaces any prior IActorProvider registration — actor-provider helpers do not stack. Pick one provider per environment (or wrap with AddCachingActorProvider<T>(IServiceCollection)); the last AddXxxActorProvider call wins.

Startup validation caveat. The matching IValidateOptions<NestedJsonPathClaimsActorOptions> runs at host startup (via ValidateOnStart) regardless of whether a later AddXxxActorProvider call replaces IActorProvider. If a consumer configures invalid nested-path options (e.g. sets ActorIdPath or PermissionsPath without ContainerClaim) and then registers a different actor-provider, host startup still fails with OptionsValidationException. Either fix the invalid options or remove the call entirely; the validator is permissive of default (unconfigured) options to avoid blocking the common "register then replace" pattern.

AddTrellisWorkerActor(IServiceCollection, Actor)

Wraps the currently-registered IActorProvider so it composes cleanly across HTTP requests and non-HTTP execution (typically a BackgroundService tick). When the wrapper resolves outside an HTTP request scope (no HttpContext), it returns systemActor; inside an HTTP request scope it delegates to the inner HTTP-side provider, preserving the standard claims/bearer/header-derived actor resolution and the Maybe.None-on-anonymous → HTTP 401 contract.

public static IServiceCollection AddTrellisWorkerActor(this IServiceCollection services, Actor systemActor)

Parameters

services IServiceCollection

The service collection.

systemActor Actor

The actor returned for non-HTTP (worker / hosted-service) execution. Construct with the permissions the worker needs to issue mediator commands and queries (e.g. new Actor("system", new HashSet<string> { "reminders:dispatch" }, ...)).

Returns

IServiceCollection

The service collection for chaining.

Examples

builder.Services.AddClaimsActorProvider(opts => opts.ActorIdClaim = "sub");
builder.Services.AddTrellisWorkerActor(new Actor(
    id: "system",
    permissions: new HashSet<string> { "reminders:dispatch", "reminders:read" },
    forbiddenPermissions: new HashSet<string>(),
    attributes: new Dictionary<string, string>()));

builder.Services.AddHostedService<ReminderDispatchWorker>();

Remarks

Order matters. Call AddTrellisWorkerActor AFTER the HTTP-side actor provider helper (AddClaimsActorProvider(IServiceCollection, Action<ClaimsActorOptions>?), AddEntraActorProvider(IServiceCollection, Action<EntraActorOptions>?), AddDevelopmentActorProvider(IServiceCollection, Action<DevelopmentActorOptions>?)) and AFTER any AddCachingActorProvider<T>(IServiceCollection) wrap. The helper captures the IActorProvider slot present at call time and re-registers a wrapper that delegates to it; calling services.AddXxxActorProvider or services.AddScoped<IActorProvider, ...>() after this helper will silently overwrite the wrapper — background-worker ticks would then resolve whatever the new provider returns instead of the configured system actor (typically None in a tick context, surfacing as Error.AuthenticationRequired on the first dispatched command). The validator catches that case at host start.

Single-registration contract. Calling AddTrellisWorkerActor twice throws — wrapping a wrapper would mean a worker scope returns the inner wrapper's system actor instead of the outer's, which is never the intended composition.

Lifetime. The wrapper is registered as scoped (matching the other built-in actor providers). Built-in providers (Claims / Entra / Development / Caching) are scoped, so the typical wiring preserves the inner's lifetime semantics exactly. The inner provider is materialized lazily on first access via a thread-safe Lazy<T> with ExecutionAndPublication — worker ticks (HttpContext null) never construct it.

Inner-descriptor support matrix.

  • Scoped via implementation type or factory: supported. Wrapper owns the materialized inner and disposes it (sync or async) when the wrapper scope ends.
  • Singleton via ImplementationInstance: supported. Wrapper delegates without re-materializing and does not dispose the instance (the consumer owns app-lifetime disposal).
  • Singleton via implementation type or factory: rejected at registration time — the wrapper is scoped, so materializing per wrapper scope would silently break the singleton invariant (N instances instead of 1). The helper throws with guidance to either re-register the provider as scoped or supply a pre-constructed instance via services.AddSingleton<IActorProvider>(instance).
  • Transient via implementation type or factory: rejected at registration time — the wrapper is scoped, so a transient inner would silently become scoped-per-wrapper (one instance reused per scope rather than a fresh instance per resolution). The helper throws with guidance to re-register as scoped.
  • Keyed registrations are ignored — the helper inspects and replaces only the unkeyed IActorProvider slot.

Decoration awareness. The wrapper implements IProvideActorVaryHeaders (delegating to the inner provider's headers) and Trellis.Asp.Authorization.IDecoratingActorProvider (so VaryForActor() diagnostics name the underlying HTTP-side provider rather than the worker wrapper).

Exceptions

ArgumentNullException

Thrown when services or systemActor is null.

InvalidOperationException

Thrown when no prior IActorProvider registration exists, when more than one prior IActorProvider descriptor is present (registration order is ambiguous), or when AddTrellisWorkerActor has already been called on this collection. A separate IHostedLifecycleService validator (Trellis.Asp.Authorization.WorkerActorRegistrationValidator) also runs at host start (in StartingAsync, before any IHostedService.StartAsync) and throws if a later registration overwrote the worker composition.
