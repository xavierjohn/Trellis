In-memory IIdempotencyStore implementation backed by a ConcurrentDictionary<TKey, TValue>. Intended for unit / integration tests and for single-instance development hosts; not safe across multiple instances or process restarts. Production hosts that need cross-instance persistence should supply their own IIdempotencyStore implementation backed by shared storage.

Remarks

All mutations use compare-and-swap (CAS) loops on the underlying dictionary so concurrent reservers contend cleanly: exactly one observes IdempotencyReservationOutcome.Reserved; the rest observe IdempotencyReservationOutcome.AlreadyInFlight.

Time is provided by TimeProvider so tests can advance the clock deterministically to exercise TTL and reservation-timeout transitions.

To bound memory in long-running hosts, the store performs an opportunistic sweep at the start of every TryReserveAsync(string, string, string, CancellationToken) call: at most once per Ttl/8, one caller walks the dictionary and removes completed entries past Ttl. Never-retried keys are therefore evicted within ~ Ttl + Ttl/8 of expiry as long as other traffic continues to arrive. A completely idle store retains expired entries indefinitely; restart the host or call TryReserveAsync(string, string, string, CancellationToken) to drain. Outstanding reservations are not swept so unrelated traffic cannot orphan a still-running slow handler; same-key retries continue to take over reservations past ReservationTimeout.

Remarks

Silently ignored if the reservation has since been taken over by another request (because ReservationTimeout elapsed).

Idempotency with CompleteAsync(string, string, string, IdempotencyResponseSnapshot, CancellationToken). IdempotencyMiddleware may invoke this method after CompleteAsync(string, string, string, IdempotencyResponseSnapshot, CancellationToken) partially succeeded — for example, a durable store that wrote the snapshot to the database but then threw during a secondary acknowledgement step. Implementations MUST NOT delete a snapshot that CompleteAsync(string, string, string, IdempotencyResponseSnapshot, CancellationToken) already persisted under the same reservationId; only an in-flight reservation may be released. A safe pattern is to short-circuit when the store-level record already has a non-null snapshot, leaving the completed entry intact for replay.
