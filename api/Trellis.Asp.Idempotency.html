Namespace Trellis.Asp.Idempotency

Classes

ActorIdempotencyScopeResolver

IIdempotencyScopeResolver that derives the scope from the current actor's id as reported by IActorProvider. Returns AnonymousScope when no actor is available.

AnonymousIdempotencyScopeResolver

Default IIdempotencyScopeResolver that returns the constant sentinel "anonymous" for every request. Safe only when the idempotency-key space is already isolated per client by some other mechanism (for example an API-gateway that issues a per-tenant API key); otherwise two authenticated users sending the same key value can replay each other's responses.

CapturingResponseBodyFeature

Decorator over an IHttpResponseBodyFeature that tees writes into a bounded in-memory capture buffer while still forwarding every byte to the original response stream. The capture is used by the idempotency middleware to record a replayable response snapshot.

DefaultIdempotencyScopeResolver

Default IIdempotencyScopeResolver registered by AddTrellisIdempotency(IServiceCollection, Action<IdempotencyOptions>?). Resolves IActorProvider from the request services at request time and uses the current actor's id as the scope, falling back to AnonymousScope when no provider is registered or the actor cannot be determined.

IdempotencyApplicationBuilderExtensions

IApplicationBuilder extensions that mount the Trellis Idempotency-Key middleware in the request pipeline.

IdempotencyFingerprint

Computes a deterministic SHA-256 fingerprint over the request components that matter for safe idempotent replay: method, path, canonicalized query, body bytes, Content-Type, Content-Encoding, and any headers listed in AdditionalFingerprintHeaders.

IdempotencyKeyParser

Parses an Idempotency-Key header value using the subset of RFC 8941 structured-fields "sf-string" required by the idempotency middleware. Accepts either a bare token (RFC 7230 tchar) or a quoted string with the escape set \ and ".

IdempotencyMiddleware

Middleware that implements the IETF Idempotency-Key header semantics. When an endpoint is marked with IdempotentAttribute and the configured method matches, the middleware buffers the request body, computes a deterministic fingerprint, and consults an IIdempotencyStore to either reserve, replay, conflict, or reject the request.

IdempotencyOptions

Configuration for IdempotencyMiddleware: header name, TTL, size limits, opted-in HTTP methods, and the set of request headers that contribute to the request fingerprint in addition to the body.

IdempotencyReservationOutcome

Closed hierarchy of outcomes from TryReserveAsync(string, string, string, CancellationToken). Exactly one of IdempotencyReservationOutcome.Reserved, IdempotencyReservationOutcome.AlreadyInFlight, IdempotencyReservationOutcome.Replay, or IdempotencyReservationOutcome.BodyHashMismatch is returned for every call.

IdempotencyReservationOutcome.AlreadyInFlight

Another request with the same key, scope, and fingerprint has an active reservation and the caller's reservation request was rejected. The middleware translates this into a 409 Conflict with a Retry-After header derived from RetryAfter.

IdempotencyReservationOutcome.BodyHashMismatch

An unexpired snapshot or outstanding reservation exists for this key+scope but the request's fingerprint does not match the stored one. The middleware translates this into the configured MismatchStatusCode (default 422). Returned both for completed snapshots (replay would not match) and for an in-flight reservation whose fingerprint differs from the new request — the latter prevents the second caller from taking over the slot with a different request fingerprint, even after the reservation timeout. Despite the outcome's name, mismatches include method, path, query, fingerprinted headers, and body bytes.

IdempotencyReservationOutcome.Replay

An unexpired completed snapshot exists for this key+scope and its fingerprint matches the request. The caller replays Snapshot verbatim to the client and skips handler execution.

IdempotencyReservationOutcome.Reserved

The key was free and has now been reserved for the calling request. The caller must proceed to execute the handler and then call either CompleteAsync(string, string, string, IdempotencyResponseSnapshot, CancellationToken) with the captured snapshot or AbandonAsync(string, string, string, CancellationToken) on failure, passing the ReservationId so the store can reject a stale completion from a request whose reservation has since been taken over.

IdempotencyResponseSnapshot

Captured representation of a previously emitted response, replayed verbatim when a retry matches the original request fingerprint.

IdempotencyServiceCollectionExtensions

Service-registration extensions for the Trellis Idempotency-Key middleware.

IdempotentAttribute

Opts an endpoint or controller in to IdempotencyMiddleware processing of the Idempotency-Key request header (IETF draft draft-ietf-httpapi-idempotency-key-header).

InMemoryIdempotencyStore

In-memory IIdempotencyStore implementation backed by a ConcurrentDictionary<TKey, TValue>. Intended for unit / integration tests and for single-instance development hosts; not safe across multiple instances or process restarts. Production hosts that need cross-instance persistence should supply their own IIdempotencyStore implementation backed by shared storage.

Interfaces

IIdempotencyScopeResolver

Resolves the scope under which an idempotency key is stored, so two clients cannot replay each other's responses by colliding on a key value.

IIdempotencyStore

Backing store for IdempotencyMiddleware. Implementations are responsible for atomically reserving keys, persisting completed snapshots, and honouring TTL and reservation-timeout expiry.
