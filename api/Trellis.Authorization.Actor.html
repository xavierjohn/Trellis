Remarks

Hydrated during authentication/middleware. Permissions should be pre-flattened from all sources (JWT roles, database groups, organizational hierarchies) before constructing the Actor so that all permission checks remain O(1).

Scoped permissions use the "Permission:Scope" convention (e.g., "Document.Edit:Tenant_A"). Add scoped entries to Permissions and check with HasPermission(string, string).

All permission and attribute lookups use ordinal (case-sensitive) comparison. Ensure consistent casing when hydrating permissions, forbidden permissions, and attributes.

Equality is identity-based. Actor is conceptually an entity — its Id is a stable, externally-meaningful principal identifier (e.g. JWT sub claim) and the other properties are point-in-time state about that principal (granted permissions and ABAC attributes change over time). Two Actor instances with the same Id are equal even when their Permissions or Attributes differ; two with different Ids are never equal. This deliberately mirrors the framework's domain-layer Trellis.Entity<TId> semantics without taking on the full IAggregate surface (Actor is an authorization-layer principal, not a domain aggregate root).

public bool Equals(Actor? other)

Parameters

other Actor

The actor to compare against.

Returns

bool

true when both actors share the same Id (ordinal comparison); otherwise false. The other properties (Permissions, ForbiddenPermissions, Attributes) are state about the principal, not part of identity, and are intentionally excluded from the equality comparison.

Remarks

Identity-based equality mirrors the domain-layer Trellis.Entity<TId> pattern without inheriting the full IAggregate contract. Two Actors with the same Id represent the same principal even when one carries a freshly-rotated permission set or a different request-bound IP address — both are point-in-time snapshots of the same actor.
