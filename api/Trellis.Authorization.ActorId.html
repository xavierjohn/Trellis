Remarks

ActorId wraps the raw claim string (typically the JWT sub or AAD oid) so that authorization-layer APIs can accept and return a domain type instead of an untyped string. Consumers that store the actor's identity at aggregate boundaries (e.g. Order.CreatedByActorId) should reuse this type to keep the principal-identity concept consistent across the framework, audit fields, and any cross-aggregate comparison that asks "did the same actor do both of these things?".

Domain identifiers (a customer ID, a tenant member ID, a domain user aggregate's primary key) are not the same concept as a principal ID. Those remain whatever VO the domain models. Use ActorId for authentication-layer principal identity only — what the auth pipeline produced — and resolve to domain identity at the application service boundary if the two differ.

Uses [Trim, NotDefault] on top of RequiredString<TSelf> so the value is trimmed on construction and an empty or whitespace-only id is rejected. This matches the original Actor constructor's ArgumentException.ThrowIfNullOrWhiteSpace guard; the trim is a deliberate, documented normalization step on top of that.
