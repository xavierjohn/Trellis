Provides pattern matching extension methods for Result types containing tuples (2-5 elements) with automatic destructuring. Match enables handling both success and failure cases inline with clean, readable code.

Examples

var response = EmailAddress.TryCreate(email)
    .Combine(FirstName.TryCreate(firstName))
    .Match(
        onSuccess: (email, firstName) => Ok(new UserDto { Email = email, Name = firstName }),
        onFailure: error => BadRequest(error.Detail)
    );

Remarks

These overloads automatically destructure tuple values, eliminating the need to manually extract tuple elements. This makes pattern matching on combined results more ergonomic and type-safe.

Key features:

  • Automatic tuple destructuring - no manual element access needed
  • Type-safe handling of both success and failure paths
  • Compile-time verification of tuple element types
  • Clean, readable syntax for complex result handling

Use Match when you need to:

  • Convert Result to another type (e.g., HTTP response, DTO)
  • Handle both success and failure paths explicitly
  • Work with tuple values from Combine operations
  • Transform results at API boundaries

Matches on a Result containing a 2-element tuple, automatically destructuring the tuple values.

public static TOut Match<T1, T2, TOut>(this Result<(T1, T2)> result, Func<T1, T2, TOut> onSuccess, Func<Error, TOut> onFailure)

Parameters

result Result<(T1, T2)>

The result to match on.

onSuccess Func<T1, T2, TOut>

Function to execute on success, receiving 2 destructured tuple values as separate parameters.

onFailure Func<Error, TOut>

Function to execute on failure, receiving the error.

Returns

TOut

The output from either the success or failure function.

Type Parameters

T1

The type of the first tuple element.

T2

The type of the second tuple element.

TOut

The type of the output from either function.

Examples

var greeting = FirstName.TryCreate("John")
    .Combine(LastName.TryCreate("Doe"))    ///     .Match(
        onSuccess: (v1, v2) => $"Hello, {v1 + ", " + v2}!",
        onFailure: error => $"Error: {error.Detail}"
    );

Remarks

The tuple is automatically destructured, so you receive individual values rather than accessing tuple members. This provides cleaner, more readable code compared to manual tuple access.

Switch<T1, T2>(Result<(T1, T2)>, Action<T1, T2>, Action<Error>)

Switches on a Result containing a 2-element tuple, automatically destructuring the tuple values for side effects.

public static void Switch<T1, T2>(this Result<(T1, T2)> result, Action<T1, T2> onSuccess, Action<Error> onFailure)

Parameters

result Result<(T1, T2)>

The result to switch on.

onSuccess Action<T1, T2>

Action to execute on success, receiving 2 destructured tuple values as separate parameters.

onFailure Action<Error>

Action to execute on failure, receiving the error.

Type Parameters

T1

The type of the first tuple element.

T2

The type of the second tuple element.

Examples

FirstName.TryCreate("John")
    .Combine(LastName.TryCreate("Doe"))    ///     .Switch(
        onSuccess: (v1, v2) => Console.WriteLine($"Success: {v1 + ", " + v2}"),
        onFailure: error => Console.WriteLine($"Error: {error.Detail}")
    );

Remarks

Unlike Match which returns a value, Switch executes actions for side effects only. Use Switch when you need to perform operations but don't need to return a result.
