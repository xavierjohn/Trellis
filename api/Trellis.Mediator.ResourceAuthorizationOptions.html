Remarks

The default policy is Propagate — every command returns the original Error.Forbidden / Error.AuthenticationRequired until the consumer opts a resource into HideAsNotFound. There is no global "hide everything" switch by design: hiding existence is a per-resource security decision and a blanket default would silently change the wire shape of every authorization failure.

Translation scope. The pipeline normalizes root Error.NotFound, Error.Gone, Error.Forbidden, and Error.AuthenticationRequired to the same public NotFound. Its type and identifier come from the configured public resource and message, and its code/detail come only from this configuration. Original metadata and causes are not copied to the public error. Other direct-resource and via-leaf errors pass through unchanged. Via intermediate/owner load failures retain their collapse-to-denial behavior.

Pipeline interaction. When a command implements both IAuthorize and IAuthorizeResource<T>, the static-permission AuthorizationBehavior runs BEFORE the resource-authorization behavior. An unauthenticated caller whose request fails the static gate sees the original 401/403 — the hide-as-NotFound translation never runs. Commands that need existence-hiding to apply to every failure mode should omit IAuthorize and let HideAsNotFound cover the resource-authorization branch alone.

Cache safety. Hidden 404s can be shared across actors regardless of body differences. Protect them with Cache-Control: no-store or private — a shared cache will otherwise serve an unauthorized actor's synthetic 404 to a later authorized actor.

Normalization applies to the resource-authorization stage, not unrelated handler errors or application response customization. It does not equalize response timing.
