AddAzureServiceBusIntegrationEventConsumer(IServiceCollection, IntegrationEventNameMap, Action<AzureServiceBusConsumerOptions>)

Receives integration events from Azure Service Bus into the transactional inbox.

public static IServiceCollection AddAzureServiceBusIntegrationEventConsumer(this IServiceCollection services, IntegrationEventNameMap nameMap, Action<AzureServiceBusConsumerOptions> configure)

Parameters

services IServiceCollection

The service collection.

nameMap IntegrationEventNameMap

Resolves a received message's wire name to its local event type.

configure Action<AzureServiceBusConsumerOptions>

Consumer configuration; must register at least one subscription.

Returns

IServiceCollection

The same service collection, for chaining.

Remarks

Requires an IInboxDispatcher registration (AddTrellisInbox<TContext>()) — consuming without one would run handlers without deduplication, which is the failure the inbox exists to prevent. The dispatcher is resolved per message from a fresh scope, so it is not required to be registered before this call.

AddAzureServiceBusIntegrationEventPublisher(IServiceCollection, IntegrationEventNameMap, Action<AzureServiceBusPublisherOptions>?)

Publishes integration events to Azure Service Bus instead of to in-process handlers.

public static IServiceCollection AddAzureServiceBusIntegrationEventPublisher(this IServiceCollection services, IntegrationEventNameMap nameMap, Action<AzureServiceBusPublisherOptions>? configure = null)

Parameters

services IServiceCollection

The service collection.

nameMap IntegrationEventNameMap

Maps each event type to the wire name that names its topic.

configure Action<AzureServiceBusPublisherOptions>

Optional publisher configuration.

Returns

IServiceCollection

The same service collection, for chaining.

Remarks

This replaces any existing IIntegrationEventPublisher registration rather than adding to it. In-process fan-out and broker publication are alternatives, not layers: registering both would deliver each event locally and over the wire, so a service subscribed to its own topic would handle everything twice. Replacing makes the choice explicit and order-independent.
