Remarks

All settings carry safe defaults. The harness applies them in this order during CreateAsync:

  1. Apply default TimeProvider, IActorProvider, domain-event capture, and tick-signal registrations.
  2. Invoke each ConfigureServices(Action<IServiceCollection>) delegate (in registration order).
  3. Invoke each ConfigureLogging(Action<ILoggingBuilder>) delegate (in registration order).
  4. Register the worker as a hosted service (fails fast if an IHostedService with the same implementation type is already registered).
  5. Build the host and resolve the harness-managed singletons.
  6. Invoke each SeedAsync(Func<IServiceProvider, CancellationToken, Task>) delegate in a dedicated DI scope (in registration order).
  7. If AutoStart is true, call host.StartAsync(); otherwise the caller must invoke harness.StartAsync() explicitly.

AutoStart

When true, CreateAsync(Action<WorkerHarnessOptions>?, CancellationToken) also calls host.StartAsync() before returning. Defaults to false so the test can subscribe to events / configure waits before the worker starts producing them.

public bool AutoStart { get; set; }

DefaultWaitTimeout

The fallback timeout used by WaitForEventAsync and WaitForTickAsync when the caller does not specify one. Measured in real time — advancing the harness's FakeTimeProvider does not consume this budget. Defaults to 5 seconds.

public TimeSpan DefaultWaitTimeout { get; set; }

InitialTime

SystemActor

The actor the harness's TestActorProvider returns by default. Worker tests typically use a system-actor identity carrying the permissions the worker's command handlers require. Defaults to Actor.Create("system", new HashSet<string>()) — an empty-permission system actor; override before the harness is built when tests need specific permissions.

SeedAsync(Func<IServiceProvider, CancellationToken, Task>)

Appends a seed delegate invoked once the host is built but before it is started. The harness creates a dedicated DI scope for each delegate so EF Core DbContext and other scoped services resolve correctly; the scope is disposed before the next delegate runs.
