Remarks

A parse failure has to satisfy two contracts at once, and no single exception type satisfies both. IParsable<TSelf> requires malformed input to be signalled with a FormatException; the ASP boundary recognizes a structured validation failure only through TrellisJsonValidationException, which is a JsonException. So the failure crosses the boundary in two hops: Parse throws this type, and the JSON converter that called Parse rethrows it as a TrellisJsonValidationException carrying the same InvalidInput.

Deriving from FormatException rather than introducing a sibling type is what keeps existing catch (FormatException) sites matching, and the base message is the unchanged flattened parse message, so a caller that catches and logs sees exactly what it saw before. The structure is strictly additional.

It lives in Trellis.Core, and is public, because it is thrown from Trellis.Primitives and caught in Trellis.Core. Making it internal would put it out of reach of the throwing sites, and moving it to Trellis.Primitives would force Core's converter to reference Primitives, inverting the dependency.
