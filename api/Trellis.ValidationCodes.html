Remarks

A reason code is the stable, localizable identity of a failure. ReasonCode and ReasonCode carry it to the wire, where a client uses it to look up its own prose rather than parsing the English in Detail. That is only worth doing if the same logical failure always arrives under the same code, which is why this set is closed and why it is declared in one place instead of spelled inline at each producer.

This vocabulary is frozen. Codes may be added in later releases; an existing code is never repointed at a different meaning and never silently renamed, because a client's catalog keys on it. A code absent from a client's catalog degrades through namespace fallback — a client that does not know string.exact-length can still fall back on string — so adding is safe in a way that redefining is not.

The freeze constrains Trellis, not the application. An application is free to emit any code it likes: FluentValidation's WithErrorCode passes through verbatim, and a domain type can hand any string to Error.InvalidInput. Nothing here is validated against application codes.

Namespace boundaries decide which code a new producer should reach for, and exist because ~210 producer sites would otherwise each answer the question differently:

format.* Lexical failures only — a CLR scalar could not be constructed from the text. This includes out-of-range-for-type: "99999999999" into an int is FormatInteger, not NumberOverflow, because no integer was ever built.
string.* A string arrived intact but did not match an expected shape. All ISO code sets live here.
number.* Validation of an already-parsed number. NumberOverflow is arithmetic only, never a parse. NumberPrecision is a parsed decimal exceeding scale or precision — malformed input is FormatDecimal.
value.*Type-agnostic presence and comparison.
fields.* The subject is a set of fields rather than one — the cross-field invariants in MaybeInvariant. Accurate whichever wire member ends up carrying the violation.
enum.*, money.*, schedule.*Domain-specific.

One code per meaning, regardless of which producer noticed it. A malformed integer is FormatInteger whether it arrived through query-string binding, a JSON body, or a generated TryCreate — a client cannot be asked to know which pipeline ran.

Remarks

Producer independence is the point: a value that fails to parse must report the same code whether it arrived as a query parameter, as a JSON scalar, or nested inside a composite. The mapping lives here, once, so a new producer cannot quietly invent a different answer for a failure the framework already has a code for.
