AggregateETagExtensions

Extension methods for ETag-based optimistic concurrency validation on aggregate results. Two modes are available — the service owner chooses which to use:

  • OptionalETag<T>(Result<T>, EntityTagValue[]?) — If-Match is optional (skips if absent)
  • RequireETag<T>(Result<T>, EntityTagValue[]?) — If-Match is required (428 if absent)
Aggregate<TId>

Base class for aggregate roots in Domain-Driven Design. An aggregate is a cluster of domain objects (entities and value objects) that form a consistency boundary. The aggregate root is the only entry point for modifications and ensures all invariants within the boundary are maintained.

Error

Closed discriminated union of Trellis error values. Domain-facing cases stay transport-neutral, while boundary-layer protocols can attach typed lower-level payloads through Error.TransportFault.

Error.Aggregate

Composition of multiple independent errors. Used when several failures occur together (e.g. parallel operations, batch validation). Nested Error.Aggregate values are flattened at construction. The constructor accepts at least one error. Boundary layers decide how to render the collection on their own wire.

Error.AuthenticationRequired

The operation requires authentication that was not supplied or could not be validated.

Error.Conflict

The request conflicts with the current state of the resource.

Error.Forbidden

Authorization policy refused the request.

Error.Gone

The resource was previously known but has been permanently removed (tombstone).

Error.InvalidInput

Inbound request payload failed semantic validation: one or more fields or rules rejected the input.

Error.InvariantViolation

Global or multi-field business invariant was violated (e.g. cross-field rule, computed constraint) outside the inbound-validation pipeline.

Error.NotFound

The requested resource does not exist.

Error.RateLimited

The caller has exceeded a usage quota; retry per Retry.

Error.TransportFault

Opaque envelope for transport-specific lower-layer failure payloads produced outside Trellis.Core. Domain code does not inspect the payload; the boundary layer that understands the transport is responsible for translation. The wrapped payload must implement ITransportFault.

Error.Unavailable

The system is temporarily unable to complete the operation; the caller should retry per Retry.

Error.Unexpected

An unhandled internal failure occurred. Code identifies the kind of failure; FaultId optionally correlates to deeper diagnostics.

ErrorRetryExtensions

Transport-neutral retry-classification helpers over the closed Error catalog. Lets workers, message consumers, and outbound-gateway callers ask "should I retry this, give up on this item, or halt the batch?" without hand-rolling parallel switch blocks against framework error types.

FaultCodes

The reason codes Trellis emits for outcomes that are not a validation failure of the caller's input — internal faults, and the conflicts and gaps a request can run into.

FieldViolation

HttpError

Closed discriminated union of HTTP-transport failures. Each case mirrors a status from the IANA HTTP Status Code Registry (RFC 9110, RFC 6585) and carries header data needed to emit an RFC-compliant response. Flows through Result<TValue> via the envelope Error.TransportFault: new Error.TransportFault(new HttpError.NotAcceptable(...)).

HttpError.PreconditionRequired

HttpError.RangeNotSatisfiable

HttpError.UnsupportedMediaType
